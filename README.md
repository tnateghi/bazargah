# بازارگاه — اتوماسیون به‌روزرسانی زیرمجموعه (خوداظهاری)

ابزار محلی برای به‌روزرسانی تعداد دام زیرمجموعه‌ها در سامانه [بازارگاه نهاده‌های کشاورزی](https://sps.bki.ir) — صفحه «افزودن زیرمجموعه خوداظهاری» — **بدون آپلود اکسل روی سایت**.

جریان برای هر شناسه: جستجو → **تعلیق** رکورد قبلی → استعلام → پر کردن اعداد جدید → ذخیره.  
پنل وب برای ساخت صف از دو فایل اکسل، پیگیری وضعیت، تست تکی و اجرای دسته‌ای است.

---

## پیش‌نیاز

- **Python 3.10+** (پیشنهاد: 3.11 یا 3.12)
- **Windows** برای اجرای ورکر در پنجرهٔ جدا (پشتیبانی اصلی); روی Linux/macOS پنل کار می‌کند ولی باز شدن کنسول جدا ممکن است متفاوت باشد
- دسترسی به `https://sps.bki.ir` و حساب کاربری معتبر
- دو فایل اکسل (توضیح در [ورودی‌ها](#ورودی‌ها))

---

## نصب روی ویندوز (ساده‌ترین روش)

1. پوشهٔ پروژه را کپی کنید یا ZIP را باز کنید.
2. روی **`install.bat`** دوبار کلیک کنید (یک‌بار؛ پایتون + پکیج‌ها + Chromium).
3. بعد روی **`start.bat`** دوبار کلیک کنید → پنل در مرورگر باز می‌شود:  
   **http://127.0.0.1:8787**

پیش‌نیاز: **Python 3.10+** از [python.org](https://www.python.org/downloads/) با تیک **Add python.exe to PATH**.

اگر نصب قبلاً انجام شده، فقط `start.bat` کافی است. برای نصب مجدد، دوباره `install.bat` را بزنید.

## ورودی‌ها

| فایل | نقش |
|:-----|:----|
| **گزارش زیرمجموعه سایت** | خروجی/گزارش HTML یا XLS از سایت (`ZirMajmoeReport` و مشابه). ترتیب ردیف‌ها = ترتیب کار در پنل (`sort_order`). |
| **آمار (اکسل)** | فایل آمار با شیت **`سراب`**. جوین روی ستون **شناسه یکتا**. |

### محاسبهٔ تعداد دام

- **دام سبک** = جمع چهار ستون گوسفند/بز (نر + ماده)
- **دام سنگین** = ستون **جمع کل دام سنگین**

فقط شناسه‌هایی که در **هر دو** فایل هستند وارد صف می‌شوند. اگر اعداد قدیم و جدید یکی باشند، وضعیت **`nochange`** می‌گیرند (نیازی به ارسال مجدد نیست).

---

## استفاده از پنل

1. **بارگذاری دو اکسل** → ساخت صف از صفر (وضعیت‌های قبلی و لاگ اجرا پاک می‌شود)
2. **ورود سایت**: نام کاربری و رمز را در پنل ذخیره کنید (`data/credentials.json` — در git نیست)
3. **تست این یکی**: فقط یک شناسه؛ برای اطمینان از فلو
4. **اجرای انتخاب‌شده‌ها**: ردیف‌های تیک‌خورده
5. **تا اینجا انجام‌شده**: علامت‌گذاری دستی ردیف‌های قبل (طبق ترتیب گزارش) تا دوباره ارسال نشوند
6. فیلتر وضعیت، صفحه‌بندی (پیش‌فرض ۲۰تایی؛ قابل انتخاب ۲۰/۵۰/۱۰۰/۲۰۰)، **پاک کردن لاگ** ورکر

### وضعیت ردیف‌ها

| وضعیت | معنی |
|:------|:-----|
| `pending` | در صف |
| `running` | در حال اجرا |
| `done` | با موفقیت (بعد از دیدن **پیام سبز** سایت) |
| `failed` | خطا — متن در ستون خطا / لاگ |
| `nochange` | اعداد عوض نشده |
| `skipped` | رد شده / دستی |

## لاگین، کپچا و مرورگر

- درخواست‌ها **بدون مرورگر واقعی** برای کل فلو ارسال نمی‌شوند.
- با شروع ورکر، **Chromium** باز می‌شود (پروفایل پایدار در `data/browser_profile/`).
- **کپچا** را خودتان یک‌بار (یا وقتی نشست منقضی شد) وارد می‌کنید؛ یوزر/پسورد از تنظیمات پنل پر می‌شود.
- پنجرهٔ مرورگر تا حد ممکن **تمام‌صفحه (maximize)** باز می‌شود.

لاگ اجرا: `data/runs/worker.log`

---

## فلو روی سایت (خلاصه)

1. لاگین  
2. جستجو با شناسه  
3. **تعلیق** زیرمجموعهٔ فعال  
4. نوع زیرمجموعه = **1**  
5. استعلام شناسه (نام دامدار باید پر شود)  
6. نوع فعالیت = **1114** (دام سبک و سنگین روستایی عشایری)  
7. تعداد سبک/سنگین → **افزودن به زیرمجموعه**  
8. موفقیت فقط وقتی تأیید می‌شود که **پیام سبز** سایت بعد از ذخیره دیده شود

## نکات و عیب‌یابی

- **محدودیت ساعتی سایت** (مثلاً ۱۴–۱۵): در لاگ «اخطار سایت» می‌بینید؛ خارج از آن بازه اجرا کنید.
- **«امکان افزودن مجدد وجود ندارد»**: تعلیق کامل نشده؛ رکورد را دوباره با ورکر تست کنید یا دستی تعلیق کنید.
- **استعلام بدون نام**: `failed` — شناسه یا وضعیت روی سایت را بررسی کنید.
- **ریست ناموفق‌ها** از پنل: `failed` → `pending`
- رمز و کوکی را commit نکنید؛ `credentials.json` و `browser_profile` محلی بمانند.
